## Зачем

Tag Manager помогает довести папку с изображениями до состояния, в котором её можно
отправлять в обучение LoRA. Для подписей можно использовать локальный tagger, VLM или
pipeline из обоих этапов: tagger собирает точные booru-теги, а VLM описывает сцену обычным
языком. Результат сохраняется рядом с картинкой и остаётся доступным для проверки и правки.

В новой версии работа собрана вокруг проекта: открываете папку, смотрите её состояние,
создаёте Preview, запускаете обработку и разбираете результат в галерее или очереди
ручной проверки. Все файлы, модели и история остаются локальными.

## Возможности

Есть два способа начать обработку: короткий автоматический план и полная экспертная
настройка. Preview ничего не записывает в dataset. Долгий запуск можно поставить на паузу,
остановить и продолжить с оставшихся файлов; каждый Run сохраняет параметры, события и
результат.

Tagger и VLM настраиваются независимо. Можно получить только теги, только описание или
гибридный caption. Для каждого этапа видны выбранная модель и фактические параметры запуска.

В галерее можно найти нужные изображения, отредактировать caption, применить изменение к
выбранным файлам или попросить модель перегенерировать их с подсказкой. Visual Search
ищет похожие сцены, композиции, объекты и позы по локальному индексу.

Перед обучением раздел «Здоровье» показывает проблемы dataset, а «Проверка» собирает
файлы, которым нужно человеческое решение. В «Ресурсах» находятся GGUF/mmproj-модели,
проверка совместимости и диагностика системы.

## Установка

Нужны Python 3.11+ и Node.js 20+. В Windows достаточно установить зависимости Python и
запустить `Start Tag Manager.bat` — при первом запуске он сам соберёт интерфейс:

```powershell
python -m pip install -r requirements.txt
```

Интерфейс можно собрать и заранее (или пересобрать вручную) через `build-frontend.bat`
либо `cd frontend; npm ci; npm run build`. Обновление до свежей версии — `update.bat`:
он подтянет изменения, обновит зависимости и пересоберёт интерфейс.

Мультимодальная GGUF-модель и её `mmproj` не входят в репозиторий. Их можно выбрать на
экране «Ресурсы»; для CUDA нужны совместимые драйверы NVIDIA. Без модели остаются доступны
сканирование, галерея, редактирование, health и review.

## Разработка

```powershell
python -m pip install -r requirements.txt
cd frontend; npm ci; npm run dev
```

API запускается отдельно: `uvicorn backend.main:app --reload --port 8000`.

Проверки: `npm run build`, `npm test` и `python -m pytest -q`. Готовый desktop launcher
рассчитан на Windows; остальные системы можно использовать через эти команды.

## Формат caption

Формат задаётся промптом. Обычный пресет оставляет в первой строке booru-теги, а ниже —
описание сцены. Массовые операции редактируют строку тегов и не задевают прозу.

## FAQ

<details>
<summary>С чего начать после установки?</summary>

Откройте папку dataset на главном экране. Tag Manager просканирует изображения и создаст
проект рядом с ними. Затем откройте «Ресурсы», выберите VLM и `mmproj`, вернитесь в проект
и сделайте Preview на нескольких файлах. Если результат устраивает, запускайте весь набор.

Preview не меняет captions. Для первого прогона это самый короткий способ проверить модель,
промпт и настройки до записи сотен файлов.

</details>

<details>
<summary>Что такое GGUF и mmproj?</summary>

Мультимодальная модель для llama.cpp обычно состоит из двух файлов. Большой `.gguf`
содержит языковую модель, а `mmproj-*.gguf` — проектор, который передаёт ей изображение.
Без подходящего `mmproj` сервер может запуститься, но модель не увидит картинку.

Оба файла должны относиться к одной модели. Проектор от другой версии или архитектуры не
подойдёт, даже если его имя выглядит похоже.

</details>

<details>
<summary>Когда использовать tagger, а когда VLM?</summary>

Tagger лучше подходит для стабильных booru-тегов: персонажей, одежды, ракурса и деталей,
которые есть в его словаре. Он работает локально и обычно заметно быстрее VLM.

VLM полезна, когда нужен связный текст, отношения между объектами, композиция или детали,
которые трудно выразить одним тегом. В гибридном pipeline Tag Manager сначала получает
теги, затем передаёт их VLM как контекст и собирает единый caption. Любой этап можно
отключить.

</details>

<details>
<summary>Нужно ли отдельно устанавливать llama.cpp?</summary>

Не обязательно. В «Ресурсах» можно установить поддерживаемую Windows-сборку llama.cpp и
запускать её из Tag Manager. Приложение проверяет модель, `mmproj` и доступную память,
после чего подбирает базовые параметры. Ручная конфигурация остаётся в экспертном режиме.

Также можно подключить уже работающий OpenAI-compatible API. Это удобно, если модель
запущена в другом приложении или на другой машине.

</details>

<details>
<summary>Чем Visual Search отличается от поиска по caption?</summary>

Обычный поиск находит слова в `.txt`. Visual Search сравнивает сами изображения: общую
сцену, композицию, объекты или позу. Для этого один раз строится локальный индекс; исходные
изображения никуда не отправляются.

После добавления или изменения файлов индекс обновляется. Первый поиск поэтому может быть
заметно дольше следующих.

</details>

<details>
<summary>Что происходит при остановке Run?</summary>

Состояние запуска и список обработанных файлов сохраняются. Run можно поставить на паузу,
остановить или повторить; команда «продолжить оставшиеся» создаёт новый запуск только для
того, что не было закончено. Файлы, отправленные на ручную проверку, остаются в очереди
Review и не теряются после перезапуска приложения.

</details>

<details>
<summary>Где хранятся настройки и история?</summary>

Пользовательские настройки и индекс проектов хранятся локально в служебной папке Tag
Manager. Состояние конкретного проекта, Run-события и provenance находятся рядом с dataset,
чтобы проект можно было восстановить без облачного аккаунта. Модели и visual-search индекс
также остаются на компьютере.

</details>
